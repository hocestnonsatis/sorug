# 1.0 freeze gate

Do **not** cut `1.0.0` until every item below holds. **1.0 is a reliability
proof, not a performance or feature threshold.** Product features wait until
after the cut; pre-1.0 work is bugfix / freshness / oracle triage only.
See also [README §1.0 freeze checklist](../README.md#10-freeze-checklist) and
[api-audit.md](api-audit.md).

## Already locked (do not reopen without a breaking minor in 0.x)

- [x] Public surface audit signed off ([api-audit.md](api-audit.md), 2026-08-07)
- [x] rust-url migration notes in [cookbook.md](cookbook.md)

## Concrete release gates

| Gate | 1.0 requirement |
| --- | --- |
| WPT parser | 100% green (badge = in-tree fixtures) |
| WPT setters | 100% green |
| WPT freshness | Upstream tracked; **serious regression** resets the clock; ordinary new upstream tests do **not** |
| Daily fuzz smoke | **≥30 consecutive calendar days** green on `main` |
| Weekly long fuzz | **≥8 consecutive weeks** green on `main` |
| Cross-oracle | Ada + Node + rust-url divergences triaged ([differential-allowlist.md](differential-allowlist.md)) |
| Public API | Audit locked; no pending breaking changes; API snapshot / `cargo semver-checks` clean at cut |
| Benchmark | Reproducible Criterion baseline documented |
| MSRV | Declared `rust-version` + CI-verified |
| Publish hygiene | CHANGELOG + docs.rs + Trusted Publishing; FFI stays `publish = false` |

**Cut path:** `≥30d daily + ≥8w weekly sustained green → 1.0 RC → final API audit → 1.0.0`

Do not delay further for “more confidence” alone once both clocks are satisfied;
users otherwise keep carrying `0.x` semver risk with little marginal gain.
Calendar alone never overrides an open correctness/security/regression problem.

### Intervention threshold

| Signal | Action |
| --- | --- |
| Normal green | **Do nothing** |
| New WPT test, behavior already correct | Fixture/update only; **do not** reset clocks |
| Node/Ada/rust-url divergence | Triage; normative result from WPT/WHATWG |
| sorug regression | Fix → **restart the affected clock** |
| Fuzz: real correctness/safety bug | Fix + restart the affected green window |
| Fuzz: flaky / infrastructure | Fix harness/CI; **do not** reset clocks |
| Fuzz: duplicate known case | Attach to existing **semantic** allowlist rule |

### Do not open PRs in this phase

- Convenience / “small” public API
- Extra `ParseError` variants
- Micro-benchmark wins (~%2 etc.)
- URLPattern prep
- Legacy rust-url quirks for compatibility

These devalue the reliability clocks. Highest-value work now: **ship no new features and keep the green chain intact.**

## Freeze readiness procedure (verify at cut time)

1. `cargo test --workspace --all-features` and WPT badges match in-tree fixture counts.
2. Confirm **≥30 consecutive days** of green `fuzz-smoke.yml` and **≥8 consecutive weeks** of green `fuzz-long.yml` on `main`; triage any new artifacts into `tests/fuzz_regressions.rs`.
3. No open GitHub issues labeled / titled `wpt-freshness` that indicate a serious regression (clock reset rule above).
4. `CHANGELOG.md` has a `1.0.0` section; README semver note says breaking only in major.
5. Tag `v1.0.0` triggers Trusted Publishing + FFI Release; confirm both workflows succeed.
6. Confirm `ffi/Cargo.toml` still has `publish = false`.

## Explicit non-goals for 1.0 (and pre-1.0)

- Quirk parity with non-WHATWG parsers / rust-url legacy quirks
- `unsafe` in the main crate for micro-wins / `parse_unchecked` escape hatches
- ICU / `idna` crates
- Richer `ParseError` variants
- Hiding `Backing` or renaming host getters
- URLPattern, DOM platform expansion, RFC3986/strict modes
- AVX-512 as a product feature; custom allocator abstractions
- New public API surface before the freeze cut

## Post-1.0 product order (not gates)

1. reqwest/hyper migration + drop-in shim (`sorug-compat`; ~80–90% scenarios)
2. WASM/JS binding
3. Node N-API
4. Benchmark-driven optimization (SIMD = implementation detail)
5. Richer diagnostics as experimental/separate API if demanded
6. Broader WHATWG surfaces only with real demand

## Cut procedure (when ready)

1. Confirm checklist above on `main`.
2. Bump to `1.0.0`, CHANGELOG entry, README semver note (“breaking only in major”).
3. Tag `v1.0.0` → Trusted Publishing + FFI release workflows.
4. Announce migration: 0.5+/cookbook is the upgrade path from rust-url.
